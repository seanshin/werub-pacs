# OHIF 뷰어 의료기기 인허가 계획

**문서 버전**: 1.0  
**작성일**: 2026-05-14  
**상태**: PLANNING  
**대상 제품**: OpenPACS OHIF Viewer (의료영상저장전송장치 소프트웨어)

---

## 1. 규제 개요

### 1.1 제품 분류

| 항목 | 내용 |
|------|------|
| **품목명** | 의료영상저장전송장치 (PACS) |
| **품목코드** | A39080.01 (의료영상송수신장치) |
| **등급** | **2등급** 의료기기 |
| **규제 경로** | 인증 (임상시험 불필요 시) 또는 허가 (임상시험 필요 시) |
| **관할 기관** | 식품의약품안전처 (MFDS) |
| **적용 법령** | 의료기기법, 디지털의료제품법 (2025.4.15 시행) |

### 1.2 법적 근거

- **의료기기법** 제6조 (등급분류), 제6조의2 (제조허가)
- **디지털의료제품 허가·인증·신고·심사 및 평가에 관한 규정** (MFDS 고시 2025-25호)
- **의료기기 소프트웨어 허가·심사 가이드라인** (2025.5 개정)
- **디지털의료기기소프트웨어 허가·심사 가이드라인** (2025.5 제정)
- **의료영상저장전송장치(PACS) 데이터 호환성 향상 및 보안 적용 가이드라인**

### 1.3 왜 인허가가 필요한가

- 의료인이 **진단 목적**으로 영상을 열람하는 소프트웨어는 의료기기에 해당
- 단순 영상 저장/전송만 하는 경우에도 2등급 의료기기로 분류
- AI 진단 보조 기능 포함 시 **3등급**으로 상향 가능 (별도 검토 필요)
- 인허가 없이 의료기관에 납품·사용 시 **의료기기법 위반** (벌칙 적용)

## 2. 인허가 절차 로드맵

```
Phase 1: 사전 준비 (2~3개월)
    ├─ 1.1 제조업 신고
    ├─ 1.2 품목 등급 확인 (식약처 사전 상담)
    ├─ 1.3 적용 표준 확인 (IEC 62304, IEC 62366, ISO 14971)
    └─ 1.4 QMS(품질경영시스템) 구축 시작

Phase 2: QMS 구축 & GMP 인증 (4~6개월)
    ├─ 2.1 ISO 13485 기반 QMS 문서 체계 수립
    ├─ 2.2 소프트웨어 생명주기 프로세스 (IEC 62304) 적용
    ├─ 2.3 위험관리 (ISO 14971) 문서 작성
    ├─ 2.4 사용적합성 (IEC 62366) 평가
    └─ 2.5 GMP 적합 인정 심사 신청 및 취득

Phase 3: 기술문서 작성 (3~4개월)
    ├─ 3.1 소프트웨어 요구사항 명세서 (SRS)
    ├─ 3.2 소프트웨어 설계 명세서 (SDS)
    ├─ 3.3 검증 및 확인(V&V) 보고서
    ├─ 3.4 성능시험 보고서
    ├─ 3.5 사이버보안 문서
    └─ 3.6 사용설명서 (한국어)

Phase 4: 기술문서 심사 (1~2개월)
    ├─ 4.1 심사기관 선정 (KTR, KTL, KCL 등)
    ├─ 4.2 기술문서 심사 접수 (25일 이내 처리)
    └─ 4.3 보완 요청 대응 (1~2회 가능)

Phase 5: 제조 인증 신청 (1개월)
    ├─ 5.1 GMP 적합인정서 + 기술문서 심사결과서 첨부
    ├─ 5.2 식약처(또는 한국의료기기안전정보원) 인증 신청
    └─ 5.3 인증서 발급 (30일 이내)

Phase 6: 사후 관리 (지속)
    ├─ 6.1 변경관리 (소프트웨어 업데이트 시)
    ├─ 6.2 GMP 정기 심사 (3년 주기)
    ├─ 6.3 부작용 보고 체계 운영
    └─ 6.4 추적관리 (의료기기 유통이력)
```

## 3. 핵심 준비 사항

### 3.1 IEC 62304 — 소프트웨어 생명주기

OHIF 뷰어의 소프트웨어 안전 등급 분류:

| 구분 | 등급 | 근거 |
|------|------|------|
| **OHIF Viewer (영상 표시)** | Class B | 오류 발생 시 진단 지연 가능 (중상 가능성 낮음) |
| **AI 추론 결과 표시** | Class C | 오진 유발 가능 (별도 인허가 필요) |
| **영상 저장/전송** | Class A | 데이터 무결성, 직접 환자 위해 낮음 |

**Class B 요구사항** (필수):
- ✅ 소프트웨어 개발 계획
- ✅ 소프트웨어 요구사항 분석
- ✅ 소프트웨어 아키텍처 설계
- ✅ 상세 설계 (해당 시)
- ✅ 단위/통합/시스템 테스트
- ✅ 소프트웨어 릴리스
- ✅ 소프트웨어 유지보수 계획

### 3.2 ISO 14971 — 위험관리

OHIF 뷰어 주요 위험 항목:

| 위험 | 심각도 | 발생확률 | 위험도 | 완화 조치 |
|------|--------|---------|--------|----------|
| 영상 표시 오류 (Window/Level) | 높음 | 낮음 | 중간 | DICOM 표준 준수, V&V 테스트 |
| 환자 정보 불일치 | 높음 | 낮음 | 중간 | UID 검증, 환자 ID 교차확인 |
| 측정값 오류 (Pixel Spacing) | 높음 | 중간 | **높음** | JPEG 밀도 검증 엔진 (Phase 3) |
| 영상 데이터 손실 | 높음 | 낮음 | 중간 | 무결성 체크, 백업 정책 |
| 무허가 접근 | 중간 | 중간 | 중간 | JWT 인증, RBAC, 감사로그 |
| AI 결과 오표시 | **높음** | 중간 | **높음** | AI 모듈 별도 인허가, 면책 표시 |

### 3.3 IEC 62366 — 사용적합성

| 항목 | 내용 |
|------|------|
| 사용 환경 | 병원 판독실, 클리닉 진료실 |
| 사용자 | 영상의학과 전문의, 임상의, 영상의학 기사 |
| 사용 시나리오 | 영상 열람, 측정, 비교 판독, 리포트 작성 |
| 위험 시나리오 | 잘못된 환자 영상 열람, 측정 오류 |
| 평가 방법 | Formative + Summative 사용적합성 테스트 |
