**작성일**: 2026-05-14

## 1. Executive Summary

### 1.1 v1.x 달성 성과

WeRU.B PACS(구 OpenPACS)는 2026년 상반기 v1.0~v1.2를 거치며 단일 기관용 웹 기반 PACS 시스템을 완성했다.

| 버전 | 주요 달성 내용 | API 수 |
|:----:|--------------|:------:|
| v1.0 | Phase 1-8 전체 완료 (DICOM 서버, 웹 뷰어, AI 연동, 판독 워크플로우, QC, 감사로그, 마이그레이션, 문서화) | 44 |
| v1.1 | 운영 안정화 — Prometheus/Grafana 모니터링, Keycloak SSO, 알림 시스템, 시스템 관리 API | 128 |
| v1.2 | 판독 기능 고도화 — 이전영상 비교, 행잉 프로토콜, 판독 통계, 오더 연동, 긴급소견 알림 | 137 |

**핵심 자산 현황:**
- **WeRU.B Viewer**: OHIF 3.13 기반 한국어 커스텀 빌드, 2D/MPR/MIP 지원
- **Admin Dashboard**: Next.js 15 기반 12개 관리 페이지 (워크리스트, 판독, 정규화, AI, 템플릿, 사용자, 감사 등)
- **판독 템플릿**: 20개 한국어 리포트 템플릿 (CT/MRI/XR/US 등 모달리티별)
- **AI 연동**: 8개 모델 파이프라인 (SOAP 자동생성, 감별진단, 비교판독)
- **HospitalRun EMR 연동**: 양방향 환자/오더 동기화
- **규제 문서**: MFDS 2등급 인허가용 25개 문서 작성 완료 (행정 심사 대기)
- **인프라**: Linode 서버, 11개 Docker 컨테이너, his.example.org 운영

### 1.2 v2.0 비전

> **"단일 기관 PACS에서 다기관 SaaS 플랫폼으로의 전환"**

v1.x가 기술적 완성도를 입증했다면, v2.0은 **멀티테넌시 아키텍처 + SaaS 사업모델**을 통해 상용화와 수익화를 실현한다.

## 3. 멀티테넌시 구현

### 3.1 아키텍처 전략: Row-Level Security (RLS)

단일 DB + RLS 방식을 선택한다. 테넌트별 DB 분리 대비 운영 비용이 낮고, PostgreSQL의 RLS 정책으로 데이터 격리를 보장할 수 있다.

```
┌─────────────────────────────────────────────────────────┐
│                    WeRU.B PACS SaaS                      │
│                                                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │ 기관 A   │  │ 기관 B   │  │ 기관 C   │  ...         │
│  │ (tenant) │  │ (tenant) │  │ (tenant) │              │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘              │
│       │              │              │                    │
│       ▼              ▼              ▼                    │
│  ┌──────────────────────────────────────────────┐       │
│  │         PostgreSQL + Row-Level Security        │       │
│  │  tenant_id 컬럼 → 모든 테이블에 적용            │       │
│  │  RLS 정책 → SELECT/INSERT/UPDATE/DELETE 격리    │       │
│  └──────────────────────────────────────────────┘       │
│                                                         │
│  ┌──────────────┐  ┌──────────────┐                     │
│  │ Orthanc Pool │  │ 공유 AI 서버  │                     │
│  │ (라우팅)     │  │ (큐 분리)    │                     │
│  └──────────────┘  └──────────────┘                     │
└─────────────────────────────────────────────────────────┘
```

### 3.2 구현 일정 (5주)

| 주차 | 작업 | 산출물 |
|:----:|------|--------|
| 1주 | DB 스키마 마이그레이션 — 전 테이블 tenant_id 추가, RLS 정책 생성 | 마이그레이션 스크립트, RLS 정책 SQL |
| 2주 | API 계층 — JWT에 tenant_id 클레임 추가, 미들웨어 자동 필터링 | FastAPI 미들웨어, Keycloak 설정 |
| 3주 | Orthanc 멀티테넌시 — 테넌트별 라벨링/필터링 플러그인 | Orthanc 플러그인, DICOMweb 라우팅 |
| 4주 | Admin Dashboard — 테넌트 관리 UI, 슈퍼관리자 대시보드 | Next.js 페이지 5개 추가 |
| 5주 | 통합 테스트, 데이터 격리 검증, 성능 테스트 | 테스트 보고서, 부하 테스트 결과 |

### 3.3 데이터 격리 보장

- **DB 레벨**: PostgreSQL RLS로 쿼리 시 자동 tenant_id 필터링
- **스토리지 레벨**: Orthanc 영상 저장소는 테넌트별 디렉토리 분리
- **캐시 레벨**: Redis 키 프리픽스에 tenant_id 포함
- **네트워크 레벨**: DICOM C-STORE 수신 시 AE Title → tenant_id 매핑
- **감사 레벨**: 모든 감사로그에 tenant_id 기록

### 6.2 WeRU.B PACS 차별화 포인트

1. **SaaS 모델**: 국내 PACS 최초 완전 클라우드 SaaS — 초기 비용 없이 시작 가능
2. **AI 내장**: 별도 AI 솔루션 구매 없이 판독 보조 AI 즉시 사용
3. **오픈 아키텍처**: REST API 137개 공개, EMR/RIS 연동 자유도 최고
4. **Zero-Footprint 뷰어**: 설치 없는 완전 웹 기반 뷰어 (모바일 포함)
5. **비표준 DICOM 대응**: 국내 유일 JPEG 밀도 조작 검출 + 자동 정규화 엔진
6. **투명한 가격**: 월 구독 명확, 숨겨진 비용 없음
