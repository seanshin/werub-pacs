# WeRU.B PACS v1.3 의료진 기능 기획서

**작성일**: 2026-05-18  
**현재 버전**: v1.2 (137 API, 25 인허가 문서)  
**목표**: 영상의학과 판독의 + 임상의 + 기사 전용 기능 강화  
**예상 기간**: 8주 (4 Sprint)

---

## 1. 배경

v1.2까지 **영상의학과 판독의 중심**으로 개발되었습니다. 실제 병원 환경에서는 판독의 외에 **임상의(주치의)**, **영상의학 기사**, **다학제 팀**이 PACS를 사용합니다. 이들의 워크플로우를 지원해야 실무 도입이 가능합니다.

### 사용자별 Pain Point

| 사용자 | 현재 문제 | 필요한 것 |
|--------|----------|----------|
| **임상의 (주치의)** | 영상/리포트 확인이 어려움 | 내 환자 전용 포털 + 리포트 알림 |
| **판독의** | 자유텍스트 리포트만 지원 | 구조화 리포트 (BI-RADS, LI-RADS) + 팔로업 추적 |
| **영상의학 기사** | 방사선량 관리 불가 | 선량 기록 + QC 체크리스트 |
| **다학제 팀** | 영상 공유/토론 수단 없음 | 케이스 컨퍼런스 도구 |

## 2. Sprint 구성

### Sprint F: 구조화 리포트 (2주)

#### F-1. BI-RADS / LI-RADS / K-TIRADS 구조화 리포트
**대상**: 판독의  
**실무 필요도**: ★★★★★

**현재**: 자유텍스트 입력만 가능  
**목표**: 체크박스 + 드롭다운으로 구조화된 판독, 카테고리 자동 산출

**구현**:
- 구조화 리포트 스키마 정의 (JSON)
  ```json
  {
    "type": "bi-rads",
    "fields": [
      {"key": "mass_shape", "label": "종괴 모양", "type": "select", "options": ["round","oval","irregular"]},
      {"key": "mass_margin", "label": "종괴 경계", "type": "select", "options": ["circumscribed","obscured","spiculated"]},
      {"key": "calcification", "label": "석회화", "type": "select", "options": ["none","benign","suspicious"]},
      {"key": "category", "label": "BI-RADS", "type": "auto", "formula": "calculate_birads()"}
    ]
  }
  ```
- 카테고리 자동 산출 로직 (BI-RADS 0~6, K-TIRADS 1~5, LI-RADS 1~5)
- 구조화 데이터 → 자유텍스트 자동 생성
- PDF 리포트 내 구조화 데이터 포함

**API**:
```
POST /api/v1/reports/structured
GET  /api/v1/reports/structured-schemas
GET  /api/v1/reports/{id}/structured-data
```

**스키마 목록** (10종):
| # | 스키마 | 모달리티 | 부위 |
|---|--------|---------|------|
| 1 | BI-RADS | MG/US | 유방 |
| 2 | K-TIRADS | US | 갑상선 |
| 3 | LI-RADS | CT/MR | 간 |
| 4 | Lung-RADS | CT | 폐 |
| 5 | PI-RADS | MR | 전립선 |
| 6 | O-RADS | US/MR | 난소 |
| 7 | C-RADS | CT | 대장 |
| 8 | Bosniak | CT/MR | 신장 낭종 |
| 9 | 척추 퇴행성 등급 | MR | 요추 |
| 10 | 골밀도 T-score | DXA | 전신 |

#### F-2. 팔로업 추적 시스템
**대상**: 판독의 + 임상의  
**실무 필요도**: ★★★★★

**현재**: 리포트에 "3개월 후 추적 권장" 텍스트만 입력  
**목표**: 추적검사 일정 등록 → 기한 도래 시 자동 알림 → 미시행 추적

**구현**:
- 리포트 서명 시 팔로업 날짜/이유 등록
- 팔로업 대기 목록 (기한 초과 건 강조)
- 주치의에게 자동 알림 (7일 전, 당일, 3일 후)
- 미시행 팔로업 월간 리포트

**API**:
```
POST /api/v1/followups
GET  /api/v1/followups?status=pending&overdue=true
PUT  /api/v1/followups/{id}/complete
GET  /api/v1/followups/overdue-report
```

**DB 모델**:
```sql
CREATE TABLE followups (
  id UUID PRIMARY KEY,
  report_id UUID REFERENCES reports(id),
  patient_id VARCHAR(64) NOT NULL,
  study_instance_uid VARCHAR(128),
  recommended_date DATE NOT NULL,
  reason TEXT NOT NULL,           -- "3개월 후 크기 변화 확인"
  category VARCHAR(32),           -- "bi-rads-3", "lung-rads-2"
  status VARCHAR(16) DEFAULT 'pending', -- pending|completed|overdue|cancelled
  completed_study_uid VARCHAR(128),     -- 추적 검사 UID (완료 시)
  notified_at TIMESTAMPTZ,
  created_by VARCHAR(128),
  created_at TIMESTAMPTZ DEFAULT now()
);
```

#### G-2. 리포트 완료 실시간 알림

### Sprint H: 방사선량 관리 + 기사 도구 (2주)

#### H-1. 방사선량 기록 (DRL — Diagnostic Reference Level)
**대상**: 영상의학 기사, 방사선 안전 관리자  
**실무 필요도**: ★★★★★

**현재**: 방사선량 정보가 DICOM에 있지만 추출/관리 안 됨  
**목표**: CT 촬영 시 선량 자동 추출 → 환자별 누적 → DRL 비교

**구현**:
- DICOM 선량 태그 자동 추출
  - (0018,0060) kVp
  - (0018,1150) Exposure Time
  - (0018,1152) Exposure
  - (0018,115E) Image Area Dose Product
  - (0018,9345) CTDIvol
  - (0018,9346) DLP
- 환자별 누적 선량 기록
- DRL 초과 시 알림 (성인 CT 흉부: CTDIvol 15mGy, DLP 600mGy·cm)
- 월간/연간 선량 통계 리포트

**API**:
```
GET  /api/v1/dose/patient/{patient_id}      — 환자별 누적 선량
GET  /api/v1/dose/statistics                — 기간별 선량 통계
GET  /api/v1/dose/drl-alerts                — DRL 초과 알림
POST /api/v1/dose/extract/{study_uid}       — 스터디에서 선량 추출
```

#### H-2. 피어 리뷰 (Peer Review)
**대상**: 판독의  
**실무 필요도**: ★★★★☆

**현재**: 판독 품질 관리 수단 없음  
**목표**: 무작위/지정 리포트를 다른 판독의가 리뷰 → 불일치 추적

**구현**:
- 리포트 무작위 샘플링 (월 5% 또는 지정)
- 리뷰어 배정 (다른 판독의)
- 동의/불일치/코멘트 기록
- 불일치 통계 (판독의별, 모달리티별)
- 분기별 피어 리뷰 리포트

**API**:
```
POST /api/v1/peer-review/assign
GET  /api/v1/peer-review/pending
PUT  /api/v1/peer-review/{id}/submit
GET  /api/v1/peer-review/statistics
```

#### H-3. 환자 영상 CD 웹 발급
**대상**: 기사, 원무과  
**실무 필요도**: ★★★★☆

**현재**: CD 굽기 기능 없음  
**목표**: 웹에서 스터디 선택 → DICOM ZIP 다운로드 (뷰어 포함)

**구현**:
- 스터디 선택 → Orthanc에서 DICOM 다운로드
- 환자 동의 확인 체크박스
- DICOM ZIP + 무료 뷰어 (WeRU.B Lite) 포함
- 다운로드 감사 로그 기록
- 익명화 옵션 (연구용)

**API**:
```
POST /api/v1/export/cd-package/{study_uid}
GET  /api/v1/export/cd-package/{job_id}/download
```

### Sprint I: 다학제 협업 (2주)

#### I-1. 케이스 컨퍼런스 도구
**대상**: 다학제 팀 (영상의학과 + 외과 + 종양내과 + 병리과)  
**실무 필요도**: ★★★★☆

**현재**: 영상 공유 수단이 교육용 공유 링크(시간 제한)만 있음  
**목표**: 컨퍼런스 세션 생성 → 케이스 등록 → 영상+리포트+메모 통합 뷰

**구현**:
- 컨퍼런스 세션 생성 (날짜, 주제, 참석자)
- 케이스 추가 (스터디 + 리포트 + 병리 결과 메모)
- 발표 모드 (환자 정보 익명화 옵션)
- 결론/권고 기록
- 회의록 PDF 생성

**API**:
```
POST /api/v1/conferences
GET  /api/v1/conferences
POST /api/v1/conferences/{id}/cases
GET  /api/v1/conferences/{id}/presentation   — 발표 모드 뷰
POST /api/v1/conferences/{id}/minutes        — 회의록 저장
```

#### I-2. 세컨드 오피니언 (Second Opinion)
**대상**: 판독의, 외부 전문가  
**실무 필요도**: ★★★★☆

**현재**: 외부 판독의에게 영상 공유 수단 없음  
**목표**: 보안 링크 생성 → 외부 전문가 접근 → 의견 수집

**구현**:
- 세컨드 오피니언 요청 생성
- 시간 제한 + IP 제한 공유 링크
- 외부 전문가 소견 입력 폼
- 원본 리포트와 비교 표시
- 요청/응답 이력 관리

**API**:
```
POST /api/v1/second-opinion/request
GET  /api/v1/second-opinion/{token}/view     — 외부 접근 (인증 불필요)
POST /api/v1/second-opinion/{token}/submit   — 소견 제출
GET  /api/v1/second-opinion/history
```

## 3. 일정 요약 (검토 반영, v1.1)

```
Sprint F-1 (2주): 구조화 리포트 프레임워크 + 핵심 3종 (BI-RADS, K-TIRADS, LI-RADS)
Sprint F-2 (1주): 나머지 7종 스키마 + 팔로업 추적 + 워크리스트 연계

총 10주
```

### 일정 변경 사유 (검토 결과)
- **F 분리**: 구조화 리포트 스키마 10종의 카테고리 산출 로직이 모두 다름 (BI-RADS: 종괴+석회화+비대칭 조합, LI-RADS: 동맥기+washout+캡슐). 핵심 3종을 먼저 완성 후 나머지 확장.
- **H 분리**: DRL의 DICOM 선량 태그 파싱이 복잡 (RDSR, CT Dose Summary 등). 피어 리뷰는 별도 Sprint로 분리.
- **G 권한 추가**: PHYSICIAN 역할이 판독 큐를 못 보게 하는 접근 제어 로직 필요.

## 6. 추가 구현 사항 (검토에서 발견된 누락)

### 6.1 구조화 리포트 → DICOM SR 내보내기
구조화 데이터를 **DICOM Structured Report** 형식으로 Orthanc에 저장. 다른 PACS와 호환 필요.
```
POST /api/v1/reports/{id}/export-dicom-sr
```

### 6.2 주치의 포털 권한 분리
PHYSICIAN 역할은:
- ✅ 내 환자 영상/리포트 조회 가능
- ❌ 전체 판독 큐 접근 불가
- ❌ 리포트 작성/서명 불가
- ❌ 관리 기능 (사용자, 템플릿, 정규화) 접근 불가

### 6.3 팔로업 → 워크리스트 자동 연계
팔로업 기한 7일 전에 워크리스트에 "추적검사 권장" 항목 자동 생성.
```
POST /api/v1/followups/{id}/create-worklist-item
```
