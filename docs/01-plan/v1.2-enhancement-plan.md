## 2. 개선 항목 (우선순위 순)

### Sprint A: 판독 워크플로우 고도화 (2주)

#### A-1. 이전 영상 비교 (Prior Study Comparison)
**실무 필요도**: ★★★★★ (판독 시 가장 많이 사용하는 기능)

**현재**: 수동으로 이전 스터디를 별도 창에서 열어야 함  
**목표**: 동일 환자의 과거 영상을 자동으로 검색하고, 좌우 분할 화면으로 비교

**구현**:
- 환자 ID 기반 이전 스터디 자동 검색 API
- WeRU.B Viewer에서 좌(현재)/우(과거) 비교 레이아웃
- 날짜순 이전 영상 목록 (드롭다운)
- 같은 모달리티 우선 매칭

```
POST /api/v1/studies/{study_uid}/priors
→ { "priors": [{ "study_uid": "...", "date": "2025-01-15", "modality": "CT" }] }
```

#### A-2. 행잉 프로토콜 (Hanging Protocol)
**실무 필요도**: ★★★★☆

**현재**: 영상이 기본 1x1 레이아웃으로만 열림  
**목표**: 모달리티/검사 부위에 따라 자동으로 최적 레이아웃 적용

**구현**:
- 모달리티별 기본 레이아웃 설정 (CT: 1x1+MPR, MR: 2x2, CR: 1x1)
- 시리즈 자동 배치 (Scout → Axial → Coronal → Sagittal)
- WeRU.B app-config.js에 `hangingProtocol` 설정
- 사용자 커스텀 레이아웃 저장

#### A-3. 오더 연동 자동 워크리스트 (MWL Integration)
**실무 필요도**: ★★★★★

**현재**: 워크리스트를 수동으로 관리  
**목표**: HospitalRun 오더 → 워크리스트 자동 생성 → 촬영 → 판독 큐

**구현**:
- HospitalRun `orders` 테이블 폴링 (30초 주기)
- RADIOLOGY 오더 → OpenPACS 워크리스트 자동 생성
- 오더 상태 변경 시 워크리스트 자동 업데이트
- Celery 주기 태스크로 구현

```python
# celery beat schedule
"sync-hr-orders": {
    "task": "app.tasks.sync_hospitalrun_orders",
    "schedule": 30.0,  # 30초마다
}
```

### Sprint B: 판독 효율성 (1주)

#### B-1. 판독 자동 분배 (Auto-assignment)
**현재**: 모든 판독의가 같은 큐를 봄  
**목표**: 모달리티/전문분야별 자동 분배

**구현**:
- 판독의별 담당 모달리티 설정 (dr.kim → CT, MR)
- 라운드로빈 또는 부하 기반 분배
- 긴급(STAT) 건은 전체 판독의에게 알림

```
PUT /api/v1/users/{id}/reading-preferences
{ "modalities": ["CT", "MR"], "max_daily": 50 }
```

#### B-2. 판독 통계 대시보드
**현재**: 대시보드에 기본 카운트만 있음  
**목표**: 판독의별/기간별 통계, 성과 분석

**구현**:
- 판독의별 일/주/월 판독 건수
- 평균 판독 시간 (리포트 열기 → 서명)
- 모달리티별 판독 분포
- TAT (Turn Around Time) 분석
- 차트 (Chart.js 또는 Recharts)

```
GET /api/v1/reports/statistics?from=2026-05-01&to=2026-05-18&group_by=reader
```

#### B-3. 긴급 소견 알림 강화 (Critical Finding Alert)
**현재**: UI에서 "긴급" 배지만 표시  
**목표**: 실시간 푸시 알림 + 이메일/SMS

**구현**:
- WebSocket 실시간 알림 (브라우저 Notification API)
- 긴급 판독 시 주치의에게 자동 알림
- 알림 확인(ACK) 추적
- 미확인 알림 에스컬레이션 (30분 후 재알림)

### Sprint C: 영상 도구 강화 (1주)

#### C-1. 측정 기록 저장 (Measurement Persistence)
**현재**: 측정값이 세션 종료 시 사라짐  
**목표**: 측정값을 DB에 저장하고, 다음 열기 시 복원

**구현**:
- 측정 데이터 저장 API
- DICOM SR로 내보내기 (선택)
- 뷰어 재열기 시 자동 복원

```
POST /api/v1/studies/{uid}/annotations
{ "measurements": [...], "key_images": [...] }
```

#### C-2. 키 이미지 마킹 (Key Image Note)
**현재**: 없음  
**목표**: 중요 영상을 마킹하고, 리포트에 첨부

**구현**:
- 뷰어에서 ⭐ 버튼으로 키 이미지 지정
- 키 이미지 목록 API
- 리포트에 키 이미지 썸네일 자동 첨부
- DICOM Key Object Selection (KOS) 생성

#### C-3. 교육/컨퍼런스 모드
**현재**: 없음  
**목표**: 환자 정보 숨기고 교육용으로 영상 공유

**구현**:
- 익명화 뷰어 모드 (환자명/ID 마스킹)
- 공유 링크 생성 (시간 제한, 비밀번호)
- 발표용 전체화면 모드
- 주석/포인터 도구

```
POST /api/v1/studies/{uid}/share
{ "anonymize": true, "expires_in": "24h", "password": "..." }
→ { "share_url": "https://his.example.org/shared/abc123" }
```

### Sprint D: 운영 고도화 (1주)

#### D-1. 영상 보관 정책 (Storage Management)
**현재**: 모든 영상 영구 보관  
**목표**: 보관 기간별 자동 아카이브/삭제

**구현**:
- 보관 정책 설정 (Hot: 1년, Warm: 5년, Archive: 영구)
- 오래된 영상 자동 압축 (JPEG2000 Lossless)
- 스토리지 사용량 알림 (80%, 90% 임계값)
- 수동 아카이브/복원 API

#### D-2. 사용자 활동 감사 강화
**현재**: 기본 감사 로그  
**목표**: 환자 영상 접근 시 상세 기록

**구현**:
- 어떤 영상을 누가 언제 얼마나 봤는지 추적
- 비정상 접근 패턴 감지 (예: 자기 부서 외 환자 조회)
- Break-the-Glass 접근 시 사유 입력 필수화
- 월간 감사 리포트 자동 생성

#### D-3. 시스템 알림 & 건강 대시보드
**현재**: Grafana (기본)  
**목표**: Admin 내장 시스템 모니터링

**구현**:
- Admin 대시보드에 시스템 상태 카드 추가 (CPU, Memory, Disk)
- Orthanc 스토리지 사용량 실시간 표시
- 서비스 상태 (모든 컨테이너 health)
- 최근 에러 로그 표시
- 이메일/Slack 알림 연동

### Sprint E: UX 마이그레이션 (1주)

#### E-1. 다크 모드
**실무 이유**: 판독실은 어두운 환경 — 밝은 UI가 눈에 피로

**구현**:
- Admin 대시보드 다크 모드 토글
- WeRU.B Viewer는 이미 다크 (OHIF 기본)
- `prefers-color-scheme` 자동 감지
- localStorage에 선호 설정 저장

#### E-2. 키보드 단축키
**실무 이유**: 판독 속도 향상 (마우스 최소화)

| 단축키 | 기능 |
|--------|------|
| `N` | 다음 미판독 건 |
| `S` | 리포트 저장 |
| `Ctrl+Enter` | 리포트 서명 |
| `T` | 템플릿 적용 |
| `V` | 뷰어 열기 |
| `Esc` | 뷰어 닫기 |

#### E-3. 판독 타이머
**실무 이유**: TAT 관리 (검사부터 판독까지 시간)

**구현**:
- 판독 시작 시 자동 타이머
- 목표 TAT 표시 (일반: 24시간, 긴급: 1시간)
- TAT 초과 시 경고 색상 변경
- 통계에 평균 TAT 포함
