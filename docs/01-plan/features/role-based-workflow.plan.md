# 역할별 워크플로우 기획서

**작성일**: 2026-05-19
**상태**: 기획
**목적**: 의료진 역할(판독의, 방사선사, 주치의, 연구자)별 필요 기능 정의 및 미흡 기능 식별

---

## 1. 역할 정의

| 역할 | Role ID | 대상 | 주요 업무 |
|------|---------|------|----------|
| **판독의** | `radiologist` | 영상의학과 전문의 | 영상 판독, 리포트 작성, 서명 |
| **방사선사** | `technologist` | 영상의학과 기사 | 영상 촬영, 업로드, QC, 워크리스트 |
| **주치의** | `physician` | 임상의 (외과, 내과 등) | 영상 조회, 리포트 확인, 의뢰 |
| **연구자** | `researcher` | 의학연구자 | 익명화, 데이터 추출, 통계 |
| **관리자** | `admin` | IT 관리자 | 시스템 설정, 사용자 관리 |

## 2. 판독의 (Radiologist) 워크플로우

```
출근 → 워크리스트 확인 → 미판독 Study 순차 열기 → 영상 판독 →
리포트 작성 → AI 보조 확인 → 서명 → 다음 미판독 이동 → 반복
```

## 3. 방사선사 (Technologist) 워크플로우

### 일상 업무 흐름
```
촬영 → 영상 확인 (품질 검수) → Orthanc 전송 → 워크리스트 등록 →
환자 정보 확인/수정 → QC (병합/분리) → 판독의에게 전달
```

### 기능 체크리스트

| # | 기능 | 상태 | 우선순위 |
|---|------|:----:|:--------:|
| 1 | DICOM 전송 (C-STORE) | ✅ | - |
| 2 | CD Import (STOW-RS 업로드) | ✅ | - |
| 3 | 워크리스트 등록/관리 | ✅ | - |
| 4 | Study 병합/분리 (QC) | ✅ | - |
| 5 | DICOM 태그 검증 | ✅ | - |
| 6 | 비표준 DICOM 정규화 | ✅ | - |
| 7 | 영상 품질 확인 (뷰어에서 빠른 체크) | ✅ | - |
| **8** | **환자 정보 수정 (PatientID, 이름 오타 수정)** | ⚠️ | **P0** |

```
├───────────────────────────────────────────────────┤
│ 환자명    │ MRN      │ 모달리티 │ 상태     │ 작업  │
│ 홍길동    │ P001     │ CT      │ 전송완료 │ [QC]  │
│ 김영희    │ P002     │ MR      │ 촬영중   │ [대기] │
```

## 7. 방사선사 ID 관리

### 현재 상태

- `Role.TECHNOLOGIST` 역할 존재 ✅
- 사용자 생성/수정/삭제 API 존재 ✅
- RBAC 접근 제어 존재 ✅

### 추가 필요

| 항목 | 설명 | 상태 |
|------|------|:----:|
| 방사선사 계정 생성 | admin에서 `technologist` 역할 지정 | ✅ 가능 |
| 촬영 기사 이름 기록 | Study 수신 시 PerformingPhysicianName 매핑 | ⚠️ 미연동 |
| 방사선사별 촬영 이력 | 기사별 촬영 건수/모달리티 통계 | ❌ 미구현 |
| 근무 시간대별 배정 | 워크리스트에서 기사 자동 배정 | ❌ 미구현 |

### DICOM 태그 매핑

방사선사 정보는 DICOM 헤더에 자동 기록되어야 합니다:

| DICOM 태그 | 내용 | 매핑 |
|------------|------|------|
| `(0008,1050)` PerformingPhysicianName | 촬영 기사명 | user.full_name |
| `(0008,1070)` OperatorsName | 장비 운영자 | user.full_name |
| `(0008,1010)` StationName | 촬영 장비명 | 장비 설정 |
| `(0040,0241)` PerformedStationAETitle | AE Title | Orthanc AET |

## 9. 응급 판독 워크플로우 (Emergency Radiology)

### 현재 상태
- `urgency` 필드 존재 (normal/non_urgent/urgent) ✅
- 긴급 소견 마킹 가능 ✅
- **실시간 알림 미구현** ❌
- **STAT 우선순위 자동 정렬 미구현** ❌
- **SLA 타이머 미구현** ❌

### 필요 기능

| # | 기능 | 우선순위 | 설명 |
|---|------|:--------:|------|
| 1 | **STAT 검사 자동 상단 표시** | P0 | 워크리스트에서 urgent Study 우선 정렬 |
| 2 | **긴급 소견 → 주치의 Push 알림** | P0 | WebSocket + 브라우저 Notification |
| 3 | **미판독 SLA 경고** | P1 | 30분/1시간 초과 시 색상 변경 |
| 4 | **온콜 판독의 지정** | P1 | 시간대별 자동 배정 |
| 5 | **응급실 전용 뷰** | P2 | ER 의사가 즉시 영상 확인 |

### 응급 판독 흐름
```
촬영 → Orthanc 수신 → 워크리스트 자동 등록 →
STAT 검사: 상단 배치 + 알림 →
판독의 판독 → urgent 마킹 시 → 주치의 즉시 알림 (WebSocket/SMS) →
SLA 초과 시 → 관리자 에스컬레이션
```

## 10. 예비 판독 (Preliminary Read)

### 교육 병원 워크플로우
```
레지던트가 예비 판독 (preliminary) → 전문의가 검토 → 최종 서명 (final)
```

### 현재 상태
- Report 상태에 `preliminary` 없음 → `draft`로 대체 가능하지만 의미가 다름
- 예비 판독자 vs 최종 판독자 구분 미지원

### 필요 변경
- `ReportStatus`에 `PRELIMINARY` 추가
- 예비 판독자 필드 (`preliminary_reader_id`)
- 최종 서명 시 예비 판독 내용 보존
