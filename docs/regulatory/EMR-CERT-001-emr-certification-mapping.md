# EMR-CERT-001 — 전자의무기록시스템(EMR) 인증제 상호운용성·보안성 매핑

**문서 목적**: 한국 **전자의무기록시스템 인증제**(한국보건의료정보원)와 OpenPACS의 관계를
정리하고, OpenPACS가 인증 대응에 기여하는 상호운용성·보안성 역량을 항목 매핑한다.
**조사일**: 2026-06-14 · **상태**: 초안(Draft) — 항목별 정밀 매핑은 공식 인증기준서 확보 후

> ⚠️ **본 문서는 별도 규제 체계**다. 기존 `docs/regulatory/`(README/QMS/TD/RM…)는
> **식약처(MFDS) 의료기기(PACS 2등급) 인증** 트랙(ISO 13485·IEC 62304·ISO 14971)이고,
> 본 문서는 **한국보건의료정보원 EMR 인증제**(의료법 §23조의2)다 — 별개 기관·별개 제도.

---

## 1. 핵심 결론 (먼저)

- **PACS는 EMR 인증제의 *직접 대상이 아니다*.** 인증 대상은 **EMR(전자의무기록) 제품**(여기선
  연동 HIS인 **HospitalRun**)과 그 제품을 쓰는 **의료기관**(사용인증)이다. PACS는 별도 시스템 클래스
  (식약처 의료기기로 별도 인증).
- **그러나 관계있다**: EMR 인증의 **상호운용성** 부문이 2주기(2025)에 **진료정보교류·건강정보
  고속도로 표준 연계**로 강화됐는데, **진료정보교류는 2019년부터 의료영상 전송을 포함**(445기관
  영상 송신)한다. 즉 인증 EMR이 영상정보를 교류하려면 **그 영상 서브시스템(=OpenPACS)이
  표준(DICOM/DICOMweb/FHIR ImagingStudy/KOS)을 충족**해야 한다 → OpenPACS가 *뒷받침*.
- **보안성** 부문(개인정보보호·접근통제·감사·암호화)은 OpenPACS의 보안 설계와 직접 정렬된다
  (2026-06-14 BTG/RBAC 하드닝 포함).

## 2. EMR 인증제 규제 개요 (2026-06 조사)

| 항목 | 내용 |
|---|---|
| 근거 | 의료법 §23조의2(전자의무기록 표준화), 시행령 §10조의8, 운영 고시 |
| 주관 | 한국보건의료정보원(K-HIS), 보건복지부 |
| 시행 | 1주기 2020.6 → **2주기 2025.1.1** |
| 체계 | **3부문(기능성·상호운용성·보안성) / 7분야 / 86항목** |
| 부문별 | 기능성(환자/처방/의무기록/진료정보제공 등, 1주기 62항목) · **상호운용성 20항목**(14→20 ↑) · **보안성 12항목**(14→12 정비) |
| 2주기 강화 | 상호운용성에 **진료정보교류·건강정보 고속도로 표준 관리 연계** 신설, 공공기관 연계 이동, 마약류 투약이력 조회 신설 |
| 인증 종류 | **제품인증**(EMR 제품) + **사용인증**(의료기관) |
| 유효기간 | 3년 · 포털 emrcert.mohw.go.kr |

## 3. 부문별 OpenPACS 매핑

### 3.1 상호운용성 (★ OpenPACS 직접 기여)

진료정보교류 표준 = **HL7 FHIR + DICOM**. KR-CDI(Korea Core Data for Interoperability,
2023.8, 14분류 77교류항목). 알려진 난제: **기관 간 DICOM 태그 불일치로 전송오류 빈발**.

| 인증 상호운용성 요구(영상 관점) | OpenPACS 보유 | 코드 |
|---|:---:|---|
| 진료정보교류 영상 송수신 | ✅ | DICOMweb, WADO `dicomweb.py`; 점대점 Q/R `dicom_remotes.py` |
| 표준 영상 매니페스트(KOS) | ✅ | `kos_service.py` (DICOM KOS) |
| 기관 간 교류 패키지(IHE XDM/XDS-I) | ✅ | `xds_export.py`, `xds_metadata.py` (ebRIM) |
| FHIR ImagingStudy/DiagnosticReport 브리지 | ✅ | `ai_advanced.py` FHIR R4 |
| HL7 v2 오더/결과(MLLP) | ✅ | `hl7_service.py`, `hl7_listener.py` |
| **비표준 DICOM 태그 검증·정규화** (교류오류 예방) | ✅✅ | DICOM 이슈 22규칙·정규화 — **인증 난제 직접 대응** |
| 표준 SR/SEG(TID 1500) | ✅ | `dicom_ai_standard.py` (highdicom) |
| **건강정보 고속도로(My Health Way) FHIR 연계** | 🟡 부분 | FHIR R4 보유, 고속도로 전용 API 프로파일 미검증 |

→ **영상 상호운용성 역량은 광범위 보유**. 핵심 난제(DICOM 태그 불일치)는 오히려 OpenPACS의
**비표준 검증/정규화**가 강점으로 작용.

### 3.2 보안성 (OpenPACS 보안 설계와 정렬)

| 인증 보안성 요구 | OpenPACS 보유 | 코드 |
|---|:---:|---|
| 접근통제(권한·인증) | ✅ | RBAC + **BTG 임상한정**(v12.3), JIT fail-closed |
| 감사로그(접근·위변조 추적) | ✅ | `audit.py` (기록 20파일) |
| 암호화(저장·전송) | ✅ | TLS1.3, pgcrypto, Fernet, PBKDF2 600k |
| 개인정보보호(비식별·익명화) | ✅ | `anonymize.py`, 출처 `provenance.py` |
| 세션·계정 보호 | ✅ | 유휴 타임아웃, 비밀번호 정책, 토큰 블랙리스트 |
| 외부보관제품 보안 | 🟡 | 백업/DR GPG 암호화 보유, 외부보관 위탁 시 별도 점검 |

### 3.3 기능성

EMR 고유 기능(원무·처방·의무기록) — **HospitalRun(EMR) 영역, PACS 무관**. PACS는 영상 판독·
리포트(`report.py`)만 진료정보제공 측면에서 간접 관련.

## 4. 갭 & 액션 (영상 상호운용성·보안 관점)

| # | 갭/확인필요 | 우선 | 액션 |
|:-:|---|:--:|---|
| 1 | 공식 **인증기준서(86항목)** 미확보 — 본 매핑은 부문 수준 | 高 | emrcert.mohw.go.kr 인증기준 세부 PDF 입수 → 항목별 매핑 |
| 2 | **진료정보교류표준 적합성** 미시험 | 高 | 보건복지부 진료정보교류표준(영상) 대조 시험, 태그셋·전송 프로파일 |
| 3 | **건강정보 고속도로** FHIR 프로파일 | 中 | My Health Way 영상 연계 규격 검토(현 FHIR R4 기반 확장) |
| 4 | KR-CDI 77 교류항목 매핑 | 中 | 영상 관련 교류항목 식별·매핑 |
| 5 | **인증 주체는 EMR(HospitalRun)** | 高 | EMR 측 인증 추진 시 PACS는 *연동 적합성*만 증빙 — 역할 분담 명확화 |

## 5. 다음 단계 (인허가 트랙)

1. **EMR vs PACS 인증 역할 확정**: EMR 인증(HospitalRun) ↔ 의료기기 인증(OpenPACS, 식약처
   기존 트랙) ↔ 본 상호운용성 증빙의 경계 정리
2. **공식 인증기준서 확보** → 상호운용성 20·보안성 12 항목별 적합/갭 정밀 매핑(EMR-CERT-002)
3. **진료정보교류표준 영상 적합성 시험** 계획(EMR-CERT-003)
4. 본 문서를 `docs/regulatory/README` 문서목록에 등재(별도 EMR 트랙으로)

> 인허가는 별도 트랙(코딩 세션과 분리). 본 문서는 **연동 적합성 관점의 갭 정리**까지이며,
> 정식 인증 신청·심사는 인허가 담당이 진행.
