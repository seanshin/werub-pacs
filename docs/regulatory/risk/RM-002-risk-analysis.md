# RM-002 위험 분석서 (Risk Analysis — FMEA)

| 항목 | 내용 |
|------|------|
| 문서 ID | RM-002 |
| 버전 | 2.0 |
| 작성일 | 2026-05-18 |
| 상태 | 승인 |
| 적용 표준 | ISO 14971:2019 |
| 제품명 | WeRU.B PACS |
| FMEA 항목 수 | 28개 |

## 1. 목적

WeRU.B PACS에 특화된 위험원을 식별하고, FMEA(Failure Mode and Effects Analysis)를 통해 각 위험의 심각도, 발생확률, 위험 수준을 평가한다. 14항목(v1.0)에서 28항목(v2.0)으로 확대하여 PACS 특화 위험을 포괄적으로 분석한다.

## 2. 위험 평가 기준

### 2.1 심각도 (Severity)

| 등급 | 정의 | 예시 |
|------|------|------|
| S1 | 무시 가능 (Negligible) | 불편, 경미한 UI 오류 |
| S2 | 경미 (Minor) | 일시적 불편, 재시도로 해결 |
| S3 | 중대 (Serious) | 진단 지연, 재촬영 필요, 데이터 일시 유실 |
| S4 | 치명 (Critical) | 오진 가능, 환자 정보 유출, 치료 계획 오류 |
| S5 | 재앙 (Catastrophic) | 직접적 환자 사망/중상 |

### 2.2 발생 확률 (Probability)

| 등급 | 정의 | 빈도 |
|------|------|------|
| P1 | 극히 드묾 | < 1/100,000 |
| P2 | 드묾 | 1/10,000 ~ 1/100,000 |
| P3 | 가끔 | 1/1,000 ~ 1/10,000 |
| P4 | 빈번 | 1/100 ~ 1/1,000 |
| P5 | 매우 빈번 | > 1/100 |

### 2.3 위험 수준 매트릭스

| S \ P | P1 | P2 | P3 | P4 | P5 |
|-------|----|----|----|----|-----|
| S5 | H | H | H | H | H |
| S4 | L | M | H | H | H |
| S3 | L | L | M | M | H |
| S2 | L | L | L | M | M |
| S1 | L | L | L | L | L |

## 3. 위험원 식별 범위

- DICOM 데이터 수신, 저장, 전송
- 영상 표시 (Window/Level, 측정, 방향, 렌더링)
- 환자 식별 정보 관리
- 인증/권한 및 데이터 보안
- AI 보조 진단 결과 표시
- 시스템 가용성 및 인프라
- 네트워크 통신 및 데이터 무결성
- 동시 접근 및 데이터 정합성
- SOUP/외부 의존성
- 운영 및 유지보수

## 6. High 위험 상세 분석 및 통제

### 6.1 R-003: 측정값 부정확 (JPEG 밀도 문제) — S4×P3=H

- **근본 원인**: 외부 장비/소프트웨어가 DICOM 영상을 JPEG 압축할 때 JFIF 헤더의 Xdensity/Ydensity를 임의 변경
- **영향**: Pixel Spacing과 실제 픽셀 간격 불일치 → 측정 도구 결과 부정확
- **통제 조치**:
  1. JPEG 밀도 교차검증 엔진 (VAL-002 API)
  2. JFIF Xdensity/Ydensity vs DICOM Pixel Spacing 자동 비교
  3. 불일치 감지 시 경고 표시 및 정규화 제안
  4. 정규화 엔진으로 자동 보정 (93% match rate)
- **잔여위험**: 정규화 후 S3×P1 = **Low**

### 6.2 R-011: 브루트포스 공격 — S4×P3=H

- **근본 원인**: 공개 인터넷 노출 서비스에 대한 자동화된 로그인 공격
- **통제 조치**:
  1. 5회 실패 시 30분 계정 잠금
  2. Rate Limiting (인증 API: 10 req/min)
  3. 감사 로그에 실패 기록 및 알림
  4. bcrypt cost factor 12 (레인보우 테이블 방어)
- **잔여위험**: S4×P1 = **Low**

### 6.3 R-014: AI 위음성 — S4×P3=H

- **근본 원인**: AI 모델의 고유한 한계, 학습 데이터 편향
- **통제 조치**:
  1. AI 결과에 "보조 참고용" 명확 표시
  2. 의사의 독립적 판독을 워크플로우 기본으로 유지
  3. 민감도/특이도 모니터링 대시보드
  4. 모델별 성능 지표 공개
- **잔여위험**: S3×P2 = **Low** (의사 독립 판독이 주 방어선)

### 6.4 R-024: JPEG 밀도 오류 (R-003과 연관) — S4×P3=H

- **근본 원인**: 다양한 DICOM 소프트웨어(3rd party viewer, CD burning SW)가 JPEG 리압축 시 밀도 메타데이터를 표준과 다르게 기록
- **통제 조치**: R-003과 동일 (JPEG 밀도 교차검증 + 정규화)
- **잔여위험**: 정규화 후 S3×P1 = **Low**

### 6.5 R-025: 문자셋 깨짐 — S4×P3=H

- **근본 원인**: 한국 의료 환경에서 EUC-KR, ISO-2022-KR 등 레거시 인코딩이 혼재. Specific Character Set 태그 누락 또는 잘못된 값
- **통제 조치**:
  1. 검증 엔진이 SpecificCharacterSet 태그 존재 및 값 확인
  2. 인코딩 불일치 감지 시 경고
  3. 정규화 엔진이 UTF-8로 안전 변환 (원본 보존)
  4. 변환 불가 시 사용자에게 수동 확인 요청
- **잔여위험**: S3×P1 = **Low**

## 7. 잔여위험 종합 평가

통제 조치 적용 후 모든 High 위험(5건)이 Low로 감소하였다. Medium 위험(12건)은 현재 수준에서 수용 가능하며, 지속적 모니터링을 수행한다.

| 통제 전 | 통제 후 |
|---------|---------|
| High: 5건 (18%) | High: 0건 (0%) |
| Medium: 12건 (43%) | Medium: 8건 (29%) |
| Low: 11건 (39%) | Low: 20건 (71%) |

상세 잔여위험 평가는 RM-003 참조.
