# SOP-011 불만처리 절차서 (Complaint Handling Procedure)

| 항목 | 내용 |
|------|------|
| 문서 ID | SOP-011 |
| 버전 | 2.0 |
| 작성일 | 2026-05-18 |
| 상태 | 승인 |
| 적용 표준 | ISO 13485:2016 §8.2.2, 의료기기법 시행규칙 제48조 |
| 제품명 | WeRU.B PACS |

## 1. 목적

WeRU.B PACS에 대한 고객(의료기관) 불만을 체계적으로 접수, 분류, 조사, 시정하고 회신하기 위한 절차를 규정한다.

## 2. 적용 범위

- 제품 기능 결함 (영상 표시 오류, API 장애, 뷰어 오작동 등)
- 성능 불만 (응답 지연, 시스템 다운타임)
- 보안 사고 (데이터 유출, 무단 접근)
- 사용성 불만 (UI/UX, 문서 불명확)
- 규제 관련 문의 (DICOM 적합성, 인허가)

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 불만 (Complaint) | 제품의 품질/안전/성능에 대한 고객의 부정적 피드백 |
| 부작용 (Adverse Event) | 환자 또는 사용자에게 해를 끼치거나 끼칠 수 있었던 사건 |
| CAPA | Corrective and Preventive Action, 시정 및 예방 조치 |

## 4. 불만 접수

### 4.1 접수 채널

| 채널 | 연락처 | 운영 시간 |
|------|--------|-----------|
| 이메일 | support@example.org | 24시간 접수 |
| 전화 | 1588-XXXX | 평일 09:00~18:00 |
| 웹 폼 | his.example.org/support | 24시간 접수 |
| 시스템 자동 | WeRU.B PACS 오류 보고 기능 | 자동 |

### 4.2 접수 정보

| 항목 | 필수/선택 | 설명 |
|------|-----------|------|
| 접수 번호 | 자동 | CMP-YYYY-NNN (예: CMP-2026-001) |
| 접수일 | 필수 | 접수 일시 |
| 불만 제기자 | 필수 | 기관명, 담당자명, 연락처 |
| 제품 버전 | 필수 | WeRU.B PACS 버전 (예: v9.5) |
| 불만 내용 | 필수 | 상세 설명 (재현 절차 포함) |
| 영향 범위 | 선택 | 영향 받은 환자/검사 수 |
| 첨부 파일 | 선택 | 스크린샷, 로그 파일 |

## 5. 불만 분류

### 5.1 심각도 분류

| 등급 | 정의 | 초기 대응 기한 | 해결 기한 |
|------|------|---------------|-----------|
| Critical | 환자 안전에 직접 영향 (영상 혼동, 측정 오류, 데이터 유실) | 4시간 | 24시간 |
| High | 주요 기능 장애 (서비스 중단, 로그인 불가, 판독 불가) | 8시간 | 48시간 |
| Medium | 기능 제한 (일부 기능 오작동, 성능 저하) | 24시간 | 5영업일 |
| Low | 사소한 문제 (UI 불편, 문서 오류) | 72시간 | 30영업일 |

### 5.2 유형 분류

| 코드 | 유형 | 예시 |
|------|------|------|
| FUN | 기능 결함 | 영상 렌더링 실패, API 500 오류 |
| PER | 성능 | 응답 3초 이상, 메모리 부족 |
| SEC | 보안 | 무단 접근, 세션 탈취 |
| USE | 사용성 | 워크플로우 혼란, 버튼 미반응 |
| DAT | 데이터 | DICOM 태그 오류, 정규화 실패 |
| DOC | 문서 | 사용설명서 오류, 가이드 부족 |

## 6. 조사 절차

### 6.1 초기 조사 (접수 후 24시간 이내)

1. QA 담당자가 불만을 검증하고 재현 가능 여부를 확인한다.
2. 관련 시스템 로그를 수집한다:
   - `audit_logs` 테이블 조회 (해당 시간대)
   - Docker 컨테이너 로그 (`docker compose logs backend orthanc`)
   - Nginx 접근 로그
3. 영향 범위를 평가한다 (영향 받은 환자/의료기관 수).
4. 부작용 가능성을 평가한다 → 해당 시 SOP-012(부작용보고)로 이관.

### 6.2 원인 분석

| 분석 방법 | 적용 대상 |
|-----------|-----------|
| 5 Why 분석 | 단순 결함 (설정 오류, 코딩 버그) |
| Fishbone (특성요인도) | 복합 원인 (환경/인적/프로세스) |
| 코드 리뷰 | 소프트웨어 결함 |
| 로그 분석 | 시스템/네트워크 장애 |

### 6.3 시정조치

1. 원인이 확인되면 SOP-008(CAPA)에 따라 시정조치를 수행한다.
2. 시정조치 유형:
   - 핫픽스 배포 (Critical/High)
   - 정기 릴리스에 포함 (Medium/Low)
   - 설정 변경 (서버/네트워크)
   - 사용설명서 개정 (사용성/문서)
3. 변경 사항은 SOP-007(변경관리)에 따라 기록한다.

## 7. 고객 회신

### 7.1 회신 내용

| 항목 | 설명 |
|------|------|
| 접수 확인 | 접수 번호, 담당자, 예상 처리 기한 |
| 중간 보고 | 조사 현황, 예상 해결 시점 (필요 시) |
| 최종 회신 | 원인, 시정조치, 재발 방지 대책, 패치 버전 |

### 7.2 회신 기한

- 접수 확인: 접수 후 4시간 이내 (Critical), 24시간 이내 (기타)
- 최종 회신: 해결 후 3영업일 이내

## 8. 추적 관리

### 8.1 불만 처리 대장

QA 책임자는 다음 항목을 포함하는 불만 처리 대장을 관리한다:

| 필드 | 설명 |
|------|------|
| 접수 번호 | CMP-YYYY-NNN |
| 접수일 | 최초 접수 일시 |
| 심각도 | Critical/High/Medium/Low |
| 유형 | FUN/PER/SEC/USE/DAT/DOC |
| 상태 | 접수/조사중/시정중/완료/종결 |
| 원인 | 근본 원인 요약 |
| 시정조치 | CAPA 번호 (해당 시) |
| 종결일 | 최종 종결 일시 |

### 8.2 KPI 모니터링 (월간)

| 지표 | 목표 |
|------|------|
| 초기 대응 시간 준수율 | 95% 이상 |
| 해결 기한 준수율 | 90% 이상 |
| 재발 건수 | 0건 |
| 불만 총 건수 추이 | 전월 대비 감소 |

## 9. 부작용 이관 기준

아래 기준에 해당하면 SOP-012(부작용보고)로 즉시 이관한다:
- 환자에게 실제 해가 발생한 경우
- 환자에게 해가 발생할 수 있었던 경우 (Near-miss)
- 영상 혼동으로 오진 가능성이 있는 경우
- 측정값 부정확으로 치료 계획에 영향을 줄 수 있는 경우
