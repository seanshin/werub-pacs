## 1. 목적

WeRU.B PACS 소프트웨어 의료기기에서 발생한 부적합 또는 잠재적 부적합에 대해 시정조치(CA) 및 예방조치(PA)를 체계적으로 수행하여 재발을 방지하고 제품 안전성을 향상하기 위한 절차를 규정한다.

## 2. 적용 범위

- 소프트웨어 결함 (Bug)
- 보안 취약점
- 사용자 불만 (Complaint)
- 내부/외부 감사 부적합 사항
- 위험관리 활동에서 식별된 문제
- 시스템 장애 및 성능 저하

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 시정(Correction) | 발견된 부적합을 제거하는 즉각 조치 |
| 시정조치(CA) | 부적합의 근본 원인을 제거하여 재발 방지 |
| 예방조치(PA) | 잠재적 부적합의 원인을 제거하여 발생 방지 |

## 4. CAPA 프로세스

### 4.1 문제 식별 및 기록
- 발생 경위, 영향 범위, 심각도 기록
- CAPA ID 부여 (CAPA-YYYY-NNN)
- 즉각 시정(Correction) 필요 시 수행

### 4.2 심각도 분류

| 등급 | 기준 | 대응 기한 |
|------|------|-----------|
| Critical | 환자 안전 위협, 데이터 손실 | 24시간 내 시정, 7일 내 CAPA |
| Major | 핵심 기능 장애, 보안 침해 | 72시간 내 시정, 30일 내 CAPA |
| Minor | 기능 제한, UI 오류 | 30일 내 CAPA |

### 4.3 근본 원인 분석 (Root Cause Analysis)
- 5 Whys 기법 또는 Fishbone Diagram 활용
- 소프트웨어 관련: 코드 결함, 설계 오류, SOUP 결함, 환경 문제 분류
- 분석 결과 문서화

### 4.4 시정/예방조치 계획 수립
- 조치 내용 구체적 기술
- 담당자 및 완료 기한 지정
- 효과성 검증 방법 정의
- 위험관리 문서 갱신 필요 여부 판단

### 4.5 조치 실행
- SOP-007 변경관리 절차에 따라 변경 수행
- 코드 수정, 테스트, 배포
- 관련 문서 갱신 (SRS, SDS, 위험분석 등)

### 4.6 효과성 검증
- 조치 완료 후 30~90일간 모니터링
- 동일/유사 문제 재발 여부 확인
- 효과성 미확인 시 CAPA 재개

## 5. WeRU.B PACS 적용 사례

### 5.1 보안 취약점 CAPA 사례
- **문제**: pydicom, python-jose, python-multipart 취약점 식별
- **시정**: 즉시 패치 적용 (pydicom 3.0.2, python-jose 3.5.0, python-multipart 0.0.29)
- **예방조치**: Dependabot 알림 활성화, 월간 의존성 스캔 프로세스 수립
- **효과성**: SBOM 기반 지속 모니터링

### 5.2 성능 저하 예방조치 사례
- **잠재 문제**: 대용량 DICOM 데이터 증가 시 응답 지연
- **예방조치**: PostgreSQL 인덱스 최적화, Redis 캐시 전략, 부하 테스트 정기 수행
- **효과성**: p95 응답시간 142ms 유지 확인
