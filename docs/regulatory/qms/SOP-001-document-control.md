# SOP-001 문서관리 절차서 (Document Control Procedure)

| 항목 | 내용 |
|------|------|
| 문서 ID | SOP-001 |
| 버전 | 2.0 |
| 작성일 | 2026-05-18 |
| 상태 | 승인 |
| 적용 표준 | ISO 13485:2016 §4.2.4, IEC 62304:2006+A1:2015 §5.1 |
| 제품명 | WeRU.B PACS |

## 1. 목적

WeRU.B PACS 의료기기의 품질경영시스템(QMS) 문서를 체계적으로 작성, 검토, 승인, 배포, 개정 및 폐기하기 위한 절차를 규정한다.

## 2. 적용 범위

본 절차는 아래 문서에 적용한다:
- 품질매뉴얼 (QM-xxx)
- 절차서 (SOP-xxx)
- 기술문서 (TD-xxx)
- 위험관리 파일 (RM-xxx)
- 사이버보안 문서 (CS-xxx)
- 사용적합성 문서 (UE-xxx)
- 설계이력파일 (Design History File)
- 양식 및 기록 (FM-xxx, REC-xxx)

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 관리 문서 (Controlled Document) | 본 절차에 따라 작성/승인/배포된 QMS 문서 |
| 현행본 (Current Version) | 가장 최신의 승인된 문서 버전 |
| 폐기본 (Obsolete) | 현행본으로 대체된 이전 버전 (보관만 함) |
| DHF | Design History File, 설계이력파일 |
| SOUP | Software of Unknown Provenance, 출처 불명 소프트웨어 |

## 5. 문서 작성 절차

### 5.1 작성

1. 작성자는 해당 분류의 문서 번호를 부여한다.
2. 문서 헤더에 문서 ID, 버전, 작성일, 상태, 적용 표준, 제품명을 기재한다.
3. 상태는 `초안`으로 설정한다.
4. Git 브랜치: `docs/<문서ID>-<버전>` (예: `docs/SOP-001-v2.0`)

### 5.2 검토

| 문서 유형 | 검토자 | 검토 기한 |
|-----------|--------|-----------|
| 품질매뉴얼 | QA 책임자 + 대표이사 | 5 영업일 |
| 절차서 (SOP) | QA 책임자 + 해당 부서장 | 3 영업일 |
| 기술문서 (TD) | 개발책임자 + QA 책임자 | 3 영업일 |
| 위험관리 (RM) | 개발책임자 + 임상전문가 | 5 영업일 |
| 사이버보안 (CS) | 보안담당자 + 개발책임자 | 3 영업일 |

### 5.3 승인

1. 검토 완료 후 승인권자가 문서 상태를 `승인`으로 변경한다.
2. 승인권자: 품질매뉴얼은 대표이사, 기타 문서는 QA 책임자.
3. Git: 승인 시 `main` 브랜치에 merge하며 Git tag 부여 (`doc/<문서ID>/v<버전>`).

### 5.4 배포

1. 승인된 문서는 GitHub 저장소 `docs/regulatory/` 디렉토리에 배포된다.
2. 배포 매체: Git 저장소 (원본), PDF 출력 (규제기관 제출용).
3. 관계자에게 이메일 또는 Slack으로 배포 통지한다.
4. 이전 버전은 `_archive/` 디렉토리로 이동하거나 Git 이력으로 관리한다.

## 6. 문서 개정 절차

### 6.1 개정 사유

- 규제 요구사항 변경 (MFDS 가이드라인 갱신 등)
- 제품 변경 (기능 추가, 아키텍처 변경)
- 내부감사/CAPA에 의한 시정조치
- 정기 검토 결과 (연 1회)

### 6.2 개정 프로세스

```
개정 요청 → 영향 분석 (SOP-007) → 문서 수정 → 검토 → 승인 → 배포
```

### 6.3 개정 이력 관리

모든 문서의 개정 이력은 문서 말미 또는 Git commit history로 추적한다.

| 버전 | 일자 | 변경 내용 | 작성자 | 승인자 |
|------|------|-----------|--------|--------|
| 1.0 | 2026-05-18 | 최초 작성 | 개발팀 | QA |
| 2.0 | 2026-05-18 | MFDS 제출용 확장 | 개발팀 | QA |

## 7. 문서 폐기 절차

1. 폐기 대상 문서를 식별한다 (후속 버전 존재 또는 제품 단종).
2. QA 책임자가 폐기 승인한다.
3. 원본은 `_archive/`에 보관하되 `[폐기]` 표시를 한다.
4. 보관 기간: 제품 수명 + 2년 (의료기기법 시행규칙 제25조).
