# SOP-002 기록관리 절차서 (Record Control Procedure)

| 항목 | 내용 |
|------|------|
| 문서 ID | SOP-002 |
| 버전 | 2.0 |
| 작성일 | 2026-05-18 |
| 상태 | 승인 |
| 적용 표준 | ISO 13485:2016 §4.2.5, 의료기기법 시행규칙 제25조 |
| 제품명 | WeRU.B PACS |

## 1. 목적

WeRU.B PACS 품질경영시스템에서 발생하는 기록을 식별, 수집, 보관, 보호, 검색 및 폐기하기 위한 절차를 규정한다.

## 2. 적용 범위

본 절차는 QMS 운영 과정에서 생성되는 모든 기록에 적용한다:
- 설계 개발 기록 (DHF, 설계 검토 회의록)
- 검증/유효성 확인 기록 (테스트 결과, V&V 보고서)
- 위험관리 기록 (FMEA, 잔여위험 평가)
- 불만/CAPA 기록
- 내부감사 기록
- 교육훈련 기록
- 경영검토 기록
- 시스템 감사 로그 (audit_logs 테이블)

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 기록 (Record) | QMS 활동의 결과를 기술한 문서로, 작성 후 변경 불가 |
| 보관 (Retention) | 기록의 물리적/전자적 유지 관리 |
| 폐기 (Disposal) | 보관 기간 만료 후 안전한 삭제 |

## 4. 기록 식별 및 분류

### 4.1 기록 분류 체계

| 분류 코드 | 기록 유형 | 생성 시점 | 담당 |
|-----------|-----------|-----------|------|
| REC-DHF | 설계이력 기록 | 각 Phase 완료 시 | 개발책임자 |
| REC-VV | 검증/확인 기록 | 테스트 수행 시 | QA |
| REC-RM | 위험관리 기록 | 위험 분석/평가 시 | 개발책임자 |
| REC-CAPA | CAPA 기록 | 부적합 발생 시 | QA |
| REC-AUD | 내부감사 기록 | 감사 수행 후 | QA |
| REC-CMR | 경영검토 기록 | 경영검토 회의 후 | 대표이사 |
| REC-TRN | 교육훈련 기록 | 교육 완료 후 | 인사/QA |
| REC-CMP | 불만 기록 | 불만 접수 시 | QA |
| REC-VIG | 부작용 보고 기록 | 사건 발생 시 | RA |
| REC-SUP | 공급업체 평가 기록 | 평가 수행 후 | QA |
| REC-SYS | 시스템 감사 로그 | 자동 생성 (실시간) | 시스템 |

## 5. 기록 수집 및 보관

### 5.1 전자 기록

| 기록 유형 | 저장 위치 | 형식 | 백업 |
|-----------|-----------|------|------|
| QMS 문서 기록 | GitHub `docs/regulatory/records/` | Markdown/PDF | Git + 로컬 백업 |
| 테스트 결과 | GitHub `tests/results/` | JSON/XML | Git |
| 감사 로그 | PostgreSQL `audit_logs` 테이블 | JSONB | WAL + 일일 백업 |
| CAPA/불만 기록 | GitHub `docs/regulatory/records/capa/` | Markdown | Git |
| 빌드/배포 로그 | Docker logs + CI/CD | Text | 30일 보관 |

### 5.2 물리적 기록 (해당 시)

- 서명된 승인 문서 원본: 잠금 캐비닛 보관
- 규제기관 제출 서류 사본: 별도 파일링

### 5.3 기록 보호

| 보호 조치 | 구현 |
|-----------|------|
| 접근 통제 | GitHub 저장소 권한 (Collaborator), DB RBAC |
| 무결성 | Git commit hash, PostgreSQL pgcrypto |
| 기밀성 | Private 저장소, TLS 1.3 전송 암호화 |
| 가용성 | 일일 자동 백업, 원격지 복제 |
| 변경 방지 | Git immutable history, audit_logs 삭제 불가 (RBAC) |

## 7. 기록 검색 및 열람

### 7.1 검색 방법

| 기록 유형 | 검색 방법 |
|-----------|-----------|
| Git 저장소 기록 | `git log`, `git show`, GitHub 검색 |
| DB 감사 로그 | WeRU.B PACS 감사 로그 조회 API (`GET /api/v1/audit-log`) |
| CAPA/불만 기록 | `docs/regulatory/records/` 디렉토리 탐색 |

### 7.2 열람 권한

| 역할 | 열람 가능 기록 |
|------|---------------|
| 대표이사 | 전체 기록 |
| QA 책임자 | 전체 QMS 기록 |
| 개발책임자 | 기술문서, DHF, V&V, 위험관리 |
| 규제담당자 | 전체 QMS 기록 (읽기 전용) |
| 일반 개발자 | 기술문서, 테스트 결과 |

## 8. 기록 폐기 절차

1. QA 책임자가 보관 기간 만료 기록을 연 1회 식별한다.
2. 폐기 대상 목록을 작성하여 대표이사 승인을 받는다.
3. 전자 기록: 복구 불가능한 방식으로 삭제 (secure erase).
4. 물리적 기록: 문서 파쇄기 사용.
5. 폐기 기록부에 폐기일, 대상, 방법, 승인자를 기재한다.
6. 법적 보관 의무 기록은 기간 만료 전 절대 폐기하지 않는다.

## 9. WeRU.B PACS 감사 로그 기록 상세

WeRU.B PACS는 `audit_logs` 테이블에 모든 시스템 활동을 자동 기록한다:

| 필드 | 설명 | 예시 |
|------|------|------|
| id | UUID (자동 생성) | `a1b2c3d4-...` |
| user_id | 수행자 ID | `admin` |
| action | 수행 행위 | `STUDY_VIEW`, `REPORT_CREATE` |
| resource | 대상 자원 | `study/1.2.840...` |
| ip_address | 접속 IP | `192.168.1.100` |
| timestamp | 수행 시각 (UTC) | `2026-05-18T10:30:00Z` |
| details | 상세 정보 (JSONB) | `{"method": "GET", "status": 200}` |

기록 삭제는 시스템 수준에서 차단되어 있으며, admin 역할도 감사 로그를 삭제할 수 없다.
