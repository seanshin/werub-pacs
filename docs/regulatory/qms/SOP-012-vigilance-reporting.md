# SOP-012 부작용보고 절차서 (Vigilance Reporting Procedure)

| 항목 | 내용 |
|------|------|
| 문서 ID | SOP-012 |
| 버전 | 2.0 |
| 작성일 | 2026-05-18 |
| 상태 | 승인 |
| 적용 표준 | 의료기기법 제31조, 시행규칙 제48조, ISO 13485:2016 §8.2.3 |
| 제품명 | WeRU.B PACS |

## 1. 목적

WeRU.B PACS 사용 중 발생한 의료기기 부작용(Adverse Event)을 식약처(MFDS)에 신속하고 정확하게 보고하기 위한 절차를 규정한다.

## 2. 적용 범위

WeRU.B PACS와 관련된 모든 부작용 및 안전성 정보:
- 사용자(의료기관) 보고 부작용
- 내부 발견 안전 문제
- 문헌/규제기관 정보에서 확인된 안전 문제
- 유사 의료기기(PACS) 관련 부작용 정보

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| 부작용 (Adverse Event) | 의료기기 사용과 관련하여 환자/사용자에게 발생한 유해 사건 |
| 중대한 부작용 | 사망, 생명 위협, 입원/입원 연장, 영구 장애를 초래한 사건 |
| 안전성 시정조치 (FSCA) | 안전을 위해 제조업체가 취하는 조치 (리콜, 패치, 안전성 공지) |
| Near-miss | 해를 끼칠 수 있었으나 실제로는 발생하지 않은 사건 |

## 4. 보고 대상 사건

### 4.1 보고 의무 사건

| 사건 유형 | WeRU.B PACS 관련 예시 |
|-----------|----------------------|
| 환자 식별 오류 | PatientID 매핑 오류로 타환자 영상 표시 |
| 영상 표시 오류 | Window/Level 오류로 병변 미표시, 좌우 반전 |
| 측정값 부정확 | Pixel Spacing 오류로 종양 크기 오측정 |
| 데이터 유실 | Study/Report 삭제, DB 장애로 판독 결과 소실 |
| 보안 침해 | 환자 정보 유출, 무단 접근으로 데이터 변조 |
| AI 오판독 | AI 보조 진단 결과 오류로 진단 혼란 초래 |
| 시스템 장애 | 응급 상황에서 PACS 접근 불가로 진단 지연 |

### 4.2 보고 제외 사건

- 사용자 조작 오류 (교육으로 해결 가능)
- 네트워크/전원 등 외부 인프라 장애
- 경미한 UI 불편 (환자 안전 무관)

## 5. 보고 기한

### 5.1 식약처 보고 기한 (의료기기법 제31조)

| 사건 유형 | 보고 기한 | 보고 양식 |
|-----------|-----------|-----------|
| 사망 또는 생명 위협 | 인지 후 15일 이내 | 의료기기 부작용 등 안전성 정보 보고서 |
| 중대한 건강 악화 | 인지 후 15일 이내 | 의료기기 부작용 등 안전성 정보 보고서 |
| 기타 부작용 | 인지 후 30일 이내 | 의료기기 부작용 등 안전성 정보 보고서 |
| 안전성 시정조치 (FSCA) | 조치 결정 후 즉시 | FSCA 보고서 |

### 5.2 내부 보고 기한

| 단계 | 기한 | 담당 |
|------|------|------|
| 사건 인지 → 내부 보고 | 24시간 이내 | 최초 인지자 |
| 내부 보고 → 초기 평가 | 48시간 이내 | QA 책임자 + 개발책임자 |
| 초기 평가 → 규제 보고 결정 | 72시간 이내 | QA 책임자 + 대표이사 |

## 6. 보고 절차

### 6.1 사건 인지 및 초기 보고

1. 최초 인지자(고객 접수, 내부 발견, 문헌 정보)가 사건을 QA 책임자에게 즉시 보고한다.
2. QA 책임자는 사건 보고서(VIG-YYYY-NNN)를 작성한다.
3. 사건 보고서 필수 항목:
   - 사건 번호, 인지 일자, 보고자
   - 환자 정보 (익명화)
   - 사건 설명 (발생 일시, 상황, 결과)
   - 사용된 제품 버전
   - 관련 시스템 로그

### 6.2 사건 평가

1. QA 책임자 + 개발책임자가 합동으로 평가한다:
   - 인과관계: 사건이 WeRU.B PACS에 기인하는가?
   - 심각도: 중대한 부작용에 해당하는가?
   - 재현성: 동일 조건에서 재발 가능한가?
   - 빈도: 유사 사건이 과거에 있었는가?

2. 평가 결과에 따른 분류:

| 판정 | 조치 |
|------|------|
| 보고 대상 (인과관계 확인/의심) | 식약처 보고 진행 |
| 보고 대상 아님 (인과관계 없음) | 내부 기록만 유지 |
| 추가 조사 필요 | 상세 조사 후 재평가 |

### 6.3 식약처 보고

1. 규제담당자(RA)가 식약처 의료기기 부작용 보고 시스템(medisafe.go.kr)에 보고서를 제출한다.
2. 보고서 포함 내용:
   - 제품 정보 (제품명, 인허가 번호, 버전)
   - 사건 설명 및 경위
   - 환자 정보 (익명화)
   - 원인 분석 결과 (확인된 경우)
   - 시정조치 현황/계획
3. 대표이사가 보고서를 최종 승인한다.

### 6.4 시정조치

| 조치 유형 | 시기 | 예시 |
|-----------|------|------|
| 긴급 패치 | 즉시 | 환자 식별 오류 수정, 영상 표시 버그 수정 |
| 안전성 공지 | 72시간 내 | 사용자 대상 안전 주의사항 발송 |
| 소프트웨어 리콜 | 결정 후 즉시 | 치명적 결함 시 이전 버전 복구 안내 |
| 기능 비활성화 | 즉시 | 문제 기능 임시 비활성화 (서버 설정) |

### 6.5 후속 보고

- 초기 보고 후 추가 정보가 확인되면 후속 보고서를 제출한다.
- 최종 조사 결과 및 시정조치 완료 보고서를 제출한다.
- 식약처 추가 자료 요청 시 기한 내 대응한다.

## 7. 안전성 시정조치 (FSCA)

FSCA 결정 시 다음을 수행한다:

1. 대표이사가 FSCA 수행을 결정/승인한다.
2. 식약처에 FSCA 보고서를 제출한다.
3. 영향 받는 모든 고객(의료기관)에 안전성 공지를 발송한다.
4. 시정조치를 수행한다 (소프트웨어 업데이트 배포).
5. 시정조치 완료 후 효과성을 검증한다.
6. 식약처에 FSCA 완료 보고서를 제출한다.

## 8. 추적 관리

### 8.1 부작용 관리 대장

| 필드 | 설명 |
|------|------|
| 사건 번호 | VIG-YYYY-NNN |
| 인지일 | 최초 인지 일자 |
| 보고일 | 식약처 보고 일자 |
| 심각도 | 중대/기타 |
| 인과관계 | 확인/의심/미확인/없음 |
| 식약처 보고 여부 | 예/아니오 |
| 시정조치 | CAPA 번호 |
| 상태 | 조사중/보고완료/종결 |

### 8.2 경영검토 보고

분기별 부작용 현황을 경영검토 회의에 보고한다:
- 보고 건수 및 유형
- 인과관계 분석 결과
- 시정조치 현황
- 재발 방지 효과성

## 9. 교육

- 전 직원: 부작용 인지 시 보고 의무 교육 (연 1회)
- QA/RA 담당자: 식약처 보고 시스템 사용 교육 (입사 시 + 변경 시)
- 개발팀: 안전 관련 결함 식별 교육 (연 1회)
